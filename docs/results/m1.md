# M1 — The Case File: results

Measured on 2026-09-30 with `openrouter/deepseek/deepseek-v4.1-flash` for the
`generator` role (see `config/models.yaml`). Ten seeds, at most 2 repairs each.

## How to reproduce

```bash
cp .env.example .env          # add OPENROUTER_API_KEY
make up                       # postgres + phoenix
uv run alibi case --seed 1    # ...repeat for seeds 1..10
```

## Things worth remembering

- With this model + prompt, the validator never had to repair a case in the
  sweep: structured output was clean (5–8 clues, 5 persons, every id resolved).
  That is convenient but also means the repair loop is not yet exercised by
  real generations — it is covered by unit tests (`tests/test_generator.py`)
  instead.
- Latency is the fragile part, not correctness: one OpenRouter call hung for
  more than seven minutes before being killed. A per-request timeout on
  `llm.py` calls (and a retry) would make unattended runs more predictable —
  candidate for M2.
- Cost is dominated by output tokens (each case is ~8–12 KB of JSON).
