# M3 — The World and MCP: results

Measured on 2026-09-30 with `openrouter/deepseek/deepseek-v4.1-flash` and
`openrouter/openai/text-embedding-3-small`, against `cases/01_blackwood_manor_1926.json`.

## How to reproduce

```bash
make up
uv run alibi play --case cases/01_blackwood_manor_1926.json --new   # terminal
uv run alibi mcp  --case cases/01_blackwood_manor_1926.json         # MCP over stdio
```

## Acceptance criteria (from docs/PLAN.md)

- [x] You can play a whole game in the terminal and win or lose.
- [x] You can play one game from an external MCP client; config snippet in the README.
- [x] Unit tests: action counting, clue discovery rules, accusation scoring,
      invalid ids return friendly errors.
- [x] A game survives an app restart (state in Postgres).

## Terminal game

Scripted full playthrough (`rooms → search library → status → inspect → accuse`):
searching the library revealed 4 clues in one action, inspecting the morphine
bottle implicated Dr Fenn, and `accuse dr_fenn morphine` returned **"Correct!"**
and ended the game as a win. Actions decrement correctly on every costly action
(20 → 19 → 18 …), free actions (`rooms`, `status`, `case`) cost nothing, and a
bad room id returns a friendly, free error.

## MCP from an external client

A real `mcp` stdio client connected to `alibi mcp` and saw eight tools:

```
accuse, case_summary, inspect, lie_detector, list_rooms, question, search_room, status
```

Calls returned the same text as the terminal (`search_room("library")` listed
the clues; `search_room("atlantis")` → `ERROR: No such room 'atlantis'. Rooms:
drawing_room, library, conservatory, kitchen, west_corridor.`). The README has
the JSON snippet for OpenCode / Claude Desktop.

## Persistence

State + case are stored as JSONB in `games`. After a search and a question, a
**fresh** `SqlGameStore` loaded the game back with identical `actions_left`,
`discovered_clues` and conversation — it survives a restart, and the same game
can be resumed from either front end.

## The `think` optimization

To keep turns fast, the private `think` step now runs only for the murderer;
innocents answer straight from the persona (`SuspectAgent(reason=...)`, default
= is-murderer). Re-ran the 10 injection attempts on an innocent with thinking
**disabled**: **10/10 stayed in character**, so nothing regressed. Each innocent
turn is now one chat call + two embeddings instead of two chat calls.

## Unit tests

`tests/test_game.py` (16 tests) covers action counting, invalid-action-is-free,
running out of actions = loss, clue discovery, inspect-requires-discovery,
empty-room search, question threading + clue awareness, the capped/free lie
detector, correct vs wrong accusation, game-over blocking, and persistence.

## Things worth remembering

- Tool docstrings are prompts: each one states the action cost, which is exactly
  what an LLM detective needs to budget its 20 actions.
- One `Game` object behind both front ends meant MCP and terminal could not
  drift apart; testing one effectively tested the other.
- Latency still dominates: `question` is the only costly LLM action, and the
  think-only-for-the-murderer tweak cuts most of it.
