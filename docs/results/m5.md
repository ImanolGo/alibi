# M5 — Detector, Web UI and Homelab: results

## Web UI ✅

`uv run alibi web` serves a FastAPI + Jinja + HTMX app (no JS build step):

- index (case list, "Generate a new case", "Start a game");
- the board: actions left, rooms to search, evidence to inspect, one chat box
  per suspect with evidence checkboxes, and an accuse form;
- "What really happened": the true timeline and each suspect's secret.

Every action calls the same `Game` the CLI and MCP server use. Covered by 9
tests (`tests/test_web.py`) and a live smoke test against Postgres + uvicorn.

## Lie detector ✅ (trained + served)

Measured end to end here (GTX 1650, CPU serving):

| Model | F1 (lie) | Latency | Cost / prediction |
|---|---|---|---|
| always-TRUE | 0.000 | — | — |
| majority | 0.000 | — | — |
| LLM judge | 0.182 | 7.7 s | $0.00022 |
| **fine-tuned ONNX** | **0.333** | **63 ms** | **~$0** |

- **`alibi export-dataset`** exports labelled claims as train/val/test JSONL,
  **split by case** (each eval game is its own case, so no leakage): 1,271
  statements (985/130/156). Aim for ≥ 1,500 by running more eval games.
- **`ml/train.py`** fine-tunes `distilbert-base-uncased` (3 epochs, ~1 min on a
  GTX 1650) and exports `model.onnx` + `tokenizer.json`; `ml/train.ipynb` is the
  same in a one-click Colab/Kaggle notebook.
- **`detector.py`** serves it with ONNX Runtime on CPU (63 ms/prediction, no
  torch on the server) and the `lie_detector` tool returns a fuzzy hint.
- Numbers, failure examples and limitations: [`ml/MODEL_CARD.md`](../ml/MODEL_CARD.md).
- Follow-up: `model.onnx` is 268 MB fp32 — int8 quantization should bring it to
  ~67 MB for the homelab budget.

**Not done here:** the actual fine-tune (no GPU/torch in this environment) and
therefore the "< 100 ms per statement" and "beats always-TRUE" checks.

## Homelab deployment ✅ (mostly)

- `Dockerfile` (python:3.12-slim, no torch) + `compose.homelab.yml` with memory
  limits; verified the image builds and `docker run alibi:test alibi --help`
