# M4 — Evals: results

## Setup

- Model (generator, suspect, solver, judge): `openrouter/deepseek/deepseek-v4.1-flash`.
- Embeddings: `openrouter/openai/text-embedding-3-small`.
- Commands: `uv run alibi eval --games 5 --seed 1` (reports to
  `docs/results/eval-<date>.md`) and `--gate` to fail on `config/gates.yaml`.
- Runs were unattended; each game generates a case, has the solver play it, and
  has the judge label every suspect answer.

## One failure I found: the mystery is too easy

`solve_rate` is pinned at 1.000 against a gate ceiling of 0.85 — the automatic
detective never loses. The first hypothesis was that `inspect` gave the game
away (it literally returned *"It casts suspicion on Mr X"* for each clue, so a
solver could tally names). I removed that leak — and the solver still won, just
slower (average 4.5 → 8.5 steps). So the binding constraint is elsewhere: the
clues are individually conclusive, and confronting the murderer with two of them
triggers a confession, which ends the game.

## What I changed, before / after

| Change | Metric | Before | After |
|---|---|---|---|
| `inspect` describes the clue but no longer names a suspect (fair play) | solve_rate | 1.000 (n=2) | 1.000 (n=4) |
| same | avg solver steps per win | ~4.5 | ~8.5 |
| `case_summary` lists suspect ids+names (solver no longer invents ids) | — | solver miscalled `accuse vane` | solver uses real ids |

The `inspect` change is honest progress on *quality* (a detective should do the
reasoning) even though it did not move the gate. Next lever for difficulty,
not yet tried: make clue `points_to` non-obvious, or stop the murderer
confessing so readily (e.g. require the detective to name the evidence
explicitly, not merely have found two clues).

## Reliability finding: generation timeouts

The case generator occasionally exceeds any reasonable request timeout — one of
five generations was abandoned at 180 s while a plain completion took ~3 s. A
hard wall-clock guard (`llm.py:_run_with_timeout`) stops this stalling a run:
the game is marked invalid and the batch continues. This is the same latency
gremlin from M1, now visible in the metrics; giving the generator its own model
or a streaming call is the follow-up.

## Judge

`truth.py`'s judge produced 139 labelled claims with only 2 contradictions and 5
intentional lies, which matches the design intent (innocents are truthful; the
murderer lies about the secret/crime). Agreement with 30 hand labels is still to
be measured (`docs/results/m4_labels.md`).
