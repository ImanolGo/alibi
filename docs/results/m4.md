# M4 — Evals: results

## Setup

- Model (generator, suspect, solver, judge): `openrouter/deepseek/deepseek-v4.1-flash`.
- Embeddings: `openrouter/openai/text-embedding-3-small`.
- Command: `uv run alibi eval --games 20 --seed 1 --gate`, unattended.
- Each game generates a case, lets the solver play it, and has the judge label
  every suspect answer. Reports land in `docs/results/eval-<date>.md`.

## ⚠️ The honest caveat

`solve_rate = 0.800` passes only because the **4 timed-out games are counted as
losses**. Of the games the solver actually finished, it won **16 / 16 = 1.000**.
So the difficulty gate is green but the mystery is still too easy — the numbers
are flattered by provider timeouts, and I'm recording that rather than claiming
a win. The real `solve_rate` among completed games is unchanged.

## The failure: too easy, and prompts alone didn't fix it

Two attempts:

1. **`inspect` leaked `points_to` names** (*"It casts suspicion on Mr X"*).
   Removed → fair play. The solver still won, just slower (avg 4.5 → 8.5 steps).
2. **Fair-play generator prompt**: circumstantial clues, ≥2 red herrings
   implicating innocents, several suspects with motive and opportunity. Valid
   cases, but the solver still won every game it finished (avg ~9 steps).

Conclusion: the binding constraint is not the clue descriptions but the
**confession mechanic** — once the detective finds two clues pointing at the
murderer and confronts them, the murderer confesses and the game ends. The next
lever is to make confession require the detective to *present the specific
evidence* (not merely have found two clues), or to make the murderer hold out
longer. Prompt-only changes were not enough, which is itself a useful result.

## Reliability finding

The provider is slow on big generations and occasionally on solver turns:
generation needed up to ~300 s (its own backstop), and 4 / 20 solver turns hit
the 180 s guard. Before the fixes, one run hung for **8 h** on an open socket.
Now a hung call is abandoned, a failed generation counts as an invalid case and
a failed solver run as a loss, so an unattended run always terminates.
