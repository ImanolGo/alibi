# M4 — Evals: results

## Setup

- Model (generator, suspect, solver, judge): `openrouter/deepseek/deepseek-v4.1-flash`.
- Embeddings: `openrouter/openai/text-embedding-3-small`.
- Command: `uv run alibi eval --games 20 --seed 1 --gate`, unattended.
- Each game generates a case, lets the solver play it, and has the judge label
  every suspect answer. Timestamped reports land in `docs/results/eval-<date>.md`.

## ⚠️ The honest conclusion: the solver still never loses

`solve_rate = 0.850` passes only because the 3 timed-out games count as losses.
**Every game the solver finished, it won: 17/17 = 1.000.** Four separate
difficulty changes made the solver work harder (steps per win roughly tripled)
but none produced a single wrong accusation:

| Change | Completed-game solve rate | Avg steps per win |
|---|---|---|
| (baseline, before M4) | 1.000 | ~4.5 |
| `inspect` no longer names the suspect | 1.000 | ~8.5 |
| fair-play generator prompt (circumstantial clues, red herrings) | 1.000 | ~9.0 |
| present-evidence confession mechanic (ADR 0005) | 1.000 | ~11.0 |
| **enforced ambiguity: ≥2 red herrings at 2 innocents (ADR 0006)** | **1.000 (17/17)** | **~12.0** |

**Interpretation:** a capable LLM detective reliably cracks a four-suspect cosy
mystery — through clue reasoning, timeline cross-checks and questioning — no
matter how we reshape the clues, prompts or confession rule. The plan's
40–85 % band is really a **human** difficulty target; a strong model sits above
it. Reaching the band would need a much larger puzzle (6–7 suspects, layered
alibis), which fights the project's "keep it small" goal.

**Recommendation:** accept this and get the human difficulty signal from the M5
web UI, where a person plays — that is the number that matters for a game.

## Metric caveat worth remembering

Counting a timed-out solver run as a loss makes `solve_rate` depend on provider
latency: 0.80 → 0.90 → 0.85 across runs is *timeout noise*, not difficulty. A
future improvement is to report `completion_rate` separately (and/or exclude
errors from `solve_rate`) so infrastructure noise cannot flatter the gate.

## Reliability findings (all fixed)

- A provider call could hang for **8 hours** on an open socket → hard
  wall-clock guard (`_run_with_timeout`); plus a per-request timeout (180 s) and
  retries, and a 300 s generator backstop.
- Failed generation now counts as an invalid case and a failed solver run as a
  loss, so an unattended batch always terminates and reports.
- `eval` preflights the database: a stopped Postgres used to produce a
  misleading all-zero report.

## Judge

confessions — innocents stay truthful, the murderer lies about the secret or the
crime, matching the design intent. Agreement with 30 hand labels is **90%**
(27/30) — see `docs/results/m4_labels.md`.
